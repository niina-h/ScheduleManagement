## 1. 全体フロー(目指す姿)

```
① ガントチャートで先々の計画を立てる(視覚的入力 → タスク一覧化)
      ↓
② 翌週の週間予定を立てる
      ・ガントチャート反映ボタンで該当週の自分の予定にタスクを反映(現行機能)
      ・定例作業も同時に登録・割当(従来通り)
      ・反映されたタスクに予定時間を手入力して保存 → 週間予定作成 完了
      ↓
③ 実績の入力
      ・当日、各ユーザーが予定に対して実績を入力して保存(現行通り)
      ↓
④ 振り返り(新機能)
      ・予定通り進んでいるか、ガント予定と実績入力の差分を毎日見えるようにする
      ・所属長・管理職が部下の状況も把握できるようにする
```

**対応順序**：上から順に①→②→③→④の順で対応していく。①②は既存機能の改善・完成、③は現状維持の確認、④が新規開発。

### 3.1 タスク1-0の詳細(2026-07-23 調査結果)

- **既に本番相当で稼働中**：`base.html`・`project_tasks.html`・`project_tasks_dashboard.html` の「ガントチャート」リンクは全て `planner_bp.planner`(新方式)を指す。旧 `project_tasks_bp.gantt`(`project_tasks_gantt.html`)は直URL打ちでしか到達できない
- **権限の抜け穴**：`planner.py` の `_resolve_target()`(L.156-174)と `/save`(L.414〜)は「試作画面のため役職制限なし」とコメントで自認。ログインさえしていれば `?user_id=` や POST の `user_id` に任意の値(他人・他部署・`0`=全員)を指定して閲覧・保存・削除ができる
- **対応方針**：`project_tasks.py` に既にある権限判定(`is_privileged`、所属一致チェック等)を `planner.py` にも適用し、一般ユーザーは自分自身のみ、管理職・マスタは配下メンバーのみを対象にできるよう制限する

### 6.1 タスク4-1の詳細(2026-07-23 調査結果)

- **`project_tasks_dashboard.html`**：プロジェクトタスクの状態管理向け多機能画面(全体ステータス・担当者別テーブル・カテゴリ別グラフ・個人進捗グラフ)。`project_task`の`status`/`progress`/`delay_days`を集計しているのみで、**実績(`daily_result`)とは無関係**。グラフ過多で「情報過多」の主因と推測
- **`comments_review`(daily.py L.586-650)**：配下メンバーの振り返りコメントを期間横断一覧する画面。`is_privileged`+`get_accessible_users`による権限スコープ設計は優秀で、そのまま管理職向け新画面に応用できる。ただしコメントのテキスト表示のみで予定/実績の数値diffは扱っていない
- **重要な既発見**：`get_task_plan_vs_actual`(models.py L.2151-2201)という関数が既に存在し、タスクの日付ベース期待進捗率と`daily_result`の実績時間から`ahead`/`ontrack`/`behind`を判定している。呼び出し元は`daily.html`(L.977-1010)のバッジ表示のみ。**ただしタスク単位・進捗率ベースであり、「その日の予定時間 vs 実績時間」という日次差分ではない**ため、4-2では日次時間単位に再設計が必要
- **方針**：新画面は「`daily_view`の予定/実績列並置レイアウト」＋「`get_task_plan_vs_actual`型のahead/ontrack/behind判定(日次時間ベースに再設計)」＋「`comments_review`の期間横断・権限スコープ」を組み合わせ、グラフ類は極力排して数値・バッジ中心にする
