本番PC システム概要図

1台の運用PC上で、予定管理システムと SNS管理ツールが同居して稼働している構成。両システムはポート・タスク名・配置フォルダが完全に分離され、独立して動作する。いずれも SYSTEM 権限で自動起動するため、ユーザーのログインは不要。

01全体構成図

利用者PC → 社内LAN → 運用PC（1台）で2システムが同居。それぞれ別ポート・別タスク・別データ領域。

予定管理システム（Flask/waitress） SNS管理ツール（Streamlit） 共有リソース（OS / Python / ネットワーク） 利用者PC
重要
両システムは ポート・タスク名・データ領域が全て別。片方のリリース作業がもう片方を停止させることは通常ない。ただし Python本体・タスクスケジューラ・ディスク・ネットワーク は共用のため、更新時は共有部への影響を必ず確認する。

03通信経路・アクセスURL

利用者は同じ運用PCのIPアドレスに、ポート番号だけを変えて2システムへアクセスする。

#方向プロトコル接続先備考
1 利用者PC → 運用PC HTTP TCP:5000 http://(運用PC-IP):5000/ 予定管理
2 利用者PC → 運用PC HTTP TCP:5010 http://(運用PC-IP):5010/ SNS管理
3 運用PC (自機確認) HTTP http://localhost:5000 / :5010 動作確認用
4 運用PC → 保管先ドライブ File I/O D:\Backup\... バックアップ

04起動・停止・状態確認コマンド

操作対象を TN "タスク名" で明示的に指定するため、片方だけの操作が確実に可能。

操作予定管理システムSNS管理ツール
状態確認 schtasks /Query /TN "ScheduleServer" schtasks /Query /TN "SnsManagementServer"
起動 schtasks /Run /TN "ScheduleServer" schtasks /Run /TN "SnsManagementServer"
停止 schtasks /End /TN "ScheduleServer" schtasks /End /TN "SnsManagementServer"
ポート占有確認 netstat -ano | findstr :5000 netstat -ano | findstr :5010
Do Not
SNS管理ツールのリリース作業中に ScheduleServer を停止・再起動しないこと。予定管理システムは業務中も稼働している。
  • 誤って両方止める操作（Get-Process python | Stop-Process 等）は禁止
  • Python 本体のバージョン更新は両システムに影響。事前に両プロジェクトの依存確認が必須
