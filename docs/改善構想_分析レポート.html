すでにある土台（活かせる資産）

構想の実現に必要なデータや仕組みの多くは、すでにコードとDBに存在します。ゼロからではなく「拡張」で届きます。

コメントの蓄積 活用可

daily_comment に日次で 振り返り・行動・上長コメントが user×date 単位で蓄積（105件）。実データは業務内容・悩み・助言まで具体的。

→ AI月次分析の材料として質・量とも十分。

認証の下地 活用可

users に password_hash / remember_token（365日・httponly・secrets製）が既にある。前回ログインの記録も token で実装済み。

→ ログイン方式への切替は「選択UIを廃し全員パスワード必須化」が主作業。

所属・上司の紐付け 活用可

dept・manager_id・dept_master が揃い、get_accessible_users が manager_id 優先→dept フォールバックで絞り込み済み。

→ 「所属ごとに管理」の骨格は動いている。

予実の判定ロジック 活用可

get_task_plan_vs_actual が実績時間÷予定工数で 遅れ/予定通り/前倒しを判定済み（本日実績画面で使用中）。

→ 進捗可視化画面へ転用できる。

NEW

新しい試み — 2つの柱

AIによる月次コメント分析 新機能

配下メンバーの1か月分の reflection/action をClaude APIで要約し、「取り組んだこと・悩み・できるようになったこと」を自動抽出。

  • マスタ/管理者向けの「育成ダッシュボード」に月次サマリーを表示
  • 成長の兆し・停滞のサインを言語化し、教育方針の起点に
  • 個人の同意・閲覧範囲（自部署配下のみ）を厳格に制御

材料は既存の daily_comment。追加はAPI連携と集計画面のみ。

実績後の進捗可視化画面 新機能

ユーザーが実績登録した直後に、自分の進捗状況を視覚的に確認できる画面。何が遅れ・進み・問題ないかを一目で。

  • タスク別の予定線 vs 実績線（既存の予実判定を図に）
  • 遅延タスクを赤ストライプで警告、前倒しは緑で表示
  • 今週の消化率・残工数・繰越の可視化

判定ロジックは既存。進捗ダッシュボードへ予実を統合する形。

気づき：現在の進捗ダッシュボードは project_task の宣言値（status/progress）だけを集計し、実績時間ベースの予実は本日実績画面でしか使われていません。この2つを統合すれば、新機能の大半は既存部品の再配置で実現できます。
AUTH

ログイン・ロール・所属統制の刷新

あなたの構想を現行3役職から4役職へ拡張し、所属単位の完全分離と、システム管理者による代理切替を加えます。

ロール体系（現行3 → 構想4）

  • システム管理者 ＝ 全権限・全所属・代理切替可 新設
  • マスタ ＝ 所属管理（統括以上）
  • 管理者 ＝ 部下管理（管理職以上）
  • 一般 ＝ 主任以下・自分のみ

判定は auth_helpers.py に集約済み。ここへ「システム管理者」を1段足すのが中心。

ログイン方式の変更

  • 「人を選択」を廃止し ID＋パスワードのログイン方式へ
  • 前回ログインの記録（remember_token は既存・365日）
  • 未設定6名への初期パスワード発行が移行時の要作業
  • ログアウトでトークンも失効させる（現状はセッションクリアのみ）

所属単位の完全分離

  • ログイン後は自所属のみを扱い、他所属には一切関与しない
  • 全画面のデータ取得を所属スコープで統一（一部は実装済み）
  • 横断参照はシステム管理者に限定

システム管理者の代理切替

  • 任意ユーザーへ成り代わり、同じ画面・同じ処理を実行
  • セッションに「実ユーザー / 代理対象」を分離保持
  • 代理中は画面上に明示バナー＋operation_logへ記録

既存の「担当者切替」を、権限を伴う本格的な代理へ昇格させる。

PLAN

実装ロードマップ（推奨順）

土台（認証・ロール・所属）を固めてから機能（分析・可視化）を載せる順です。各フェーズは独立してリリース可能な単位に区切っています。

PHASE 1
認証の刷新
規模 M
  • ログイン方式へ移行：全員パスワード必須、ID＋PW入力、初期PW一括発行
  • 前回ログイン記録を全ロールへ（現状は管理職/マスタのみ）、ログアウトでtoken失効
  • 移行時に既存セッション・未設定6名のPW初期化を安全に実施
PHASE 2
ロールと所属統制
規模 L
  • 4段階ロールを auth_helpers.py に定義（システム管理者を最上位に）
  • 所属の完全分離：全データ取得を所属スコープに統一、他所属を遮断
  • ユーザー管理画面をロール階層に合わせて再構成
PHASE 3
代理切替
規模 L
  • システム管理者の成り代わり：実/代理ユーザーをセッション分離
  • 閲覧だけでなく処理も代理対象として実行、明示バナー＋監査ログ
PHASE 4
進捗の可視化
規模 M
  • 実績登録後の個人進捗画面（遅れ/進み/問題を視覚化）
  • 進捗ダッシュボードへ予実（実績時間ベース）を統合
PHASE 5
AI育成分析
規模 M
  • 月次コメントのAI要約（取り組み・悩み・成長）を Claude API で生成
  • マスタ/管理者向け育成ダッシュボード、教育方針の起点に
  • プライバシー：自部署配下のみ・生成物の保存範囲を明確化
現行コード（auth / project_task / weekly_schedule / daily_result / daily_comment）と実DB（8ユーザー・15テーブル）の分析にもとづく構想メモ。実装着手前に、各フェーズの詳細設計（データ移行・権限マトリクス・API利用範囲）を別途固めることを推奨します。
